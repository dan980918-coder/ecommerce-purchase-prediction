## 3-2. 업무 관점 요약

### CRM 담당자가 이 데이터로 알 수 있는 것 (5~7개, 실제 확인한 사실 기준)

1. 고객이 **언제** 어떤 상품을 담고(add_to_cart), 뺐고(remove_from_cart), 샀는지(product_buy) — 초 단위 타임스탬프와 sku로 확인 가능
2. 고객이 **어느 페이지를(page_visit)** 언제 방문했는지 — 다만 어떤 상품 페이지인지는 알 수 없음(url↔sku 연결키 없음)
3. 고객이 **언제 검색을 했는지**와 검색 횟수 — 다만 검색어 원문은 알 수 없음(양자화 임베딩만 존재)
4. 상품의 **카테고리(익명 ID)**와 **구간화된 가격대(0~99)** — 실제 금액은 아니지만 상대적 가격 수준 비교는 가능
5. 고객이 **5개 행동 테이블 중 어디에 등장하는지(커버리지)** — 예: 전체 고객의 84.3%는 page_visit에만 등장하고 다른 행동은 없음
6. 고객별 **행동 빈도(이벤트 수)**의 분포 — 중앙값·p90·p99·최댓값 등으로 활동 수준 비교 가능
7. 같은 고객이 **동시(같은 초)에 여러 상품을 구매한 경우**를 (client_id, timestamp) 단위로 근사적으로 묶어볼 수 있음(장바구니/주문 근사치, 한계는 있음)

### 알 수 없는 것 (5~7개, 실제 확인한 사실 기준)

1. **실제 결제 금액** — product_properties.price는 0~99 구간화 지수이며 실제 통화 단위 금액이 아님(확인: 고유값 100개뿐)
2. **마케팅 메시지 발송·노출 이력** — 이메일/푸시/광고 발송 여부, 열람·클릭 여부를 담은 테이블이나 컬럼이 데이터에 없음
3. **고객 인구통계 정보** — 연령, 성별, 지역, 가입일 등 고객 속성 컬럼이 전혀 없음(client_id만 존재)
4. **주문 단위 정보** — product_buy에 order_id 같은 주문 식별자가 없어 "한 주문에 몇 개를 샀는지"는 (client_id, timestamp) 근사로만 추정 가능하고 정확하지 않음
5. **검색어 원문** — search_query.query는 원문이 아닌 16차원 양자화 임베딩 문자열
6. **상품명 원문** — product_properties.name도 동일하게 양자화 임베딩이며, 실제 상품명을 알 수 없음
7. **page_visit이 어떤 상품/카테고리 페이지인지** — url이 sku와 연결되는 공식 키가 없어 방문 페이지의 의미를 알 수 없음

## 이 데이터로 할 수 없는 분석

- **캠페인 효과 측정** — 어떤 고객이 어떤 마케팅 메시지를 언제 받았는지 기록이 전혀 없어, 특정 캠페인과 이후 행동을 연결할 방법이 없음
- **매출액(금액) 기준 분석** — price가 실제 통화 금액이 아닌 0~99 구간화 지수이므로, 매출 합계·객단가·LTV(금액 기준) 등을 계산할 수 없음
- **인구통계 기반 세그먼트** — 연령/성별/지역 등 속성이 없어 전통적 인구통계 기반 타겟팅 분석이 불가능
- **검색어 의도 분석(텍스트 마이닝)** — 검색어가 원문이 아닌 양자화 임베딩이라 키워드 빈도, 토큰화, 의미 분석을 직접 할 수 없음
- **정확한 주문/장바구니 단위 분석** — 주문 ID가 없어 "한 번의 결제에 몇 개 상품이 포함됐는지"를 (client_id, timestamp) 근사 없이는 알 수 없고, 이 근사치는 동시각 우연 충돌과 실제 주문을 구분하지 못함(데이터 품질 문제 참고)
- **상품 페이지 방문 기반 사전 탐색 분석** — page_visit.url이 product_properties.sku와 연결되지 않아 "구매 전 어떤 상품 페이지를 봤는지"를 직접 재구성할 수 없음
- **관측 기간 이전/이후를 포함하는 전체 생애주기 분석** — 좌우측 검열로 인해 기간 경계 근처 고객의 실제 가입 시점·이탈 여부를 데이터만으로 확정할 수 없음
