# 07. 스냅샷 설계와 변수 정의

생성 스크립트: [`10_build_snapshots.py`](../scripts/10_build_snapshots.py), [`11_build_features.py`](../scripts/11_build_features.py) · 원시 결과: [`snapshot_results.json`](snapshot_results.json), [`features_summary.json`](features_summary.json)

## 1. 스냅샷 설계

### 1-1. 기준일과 기간

| 구분 | 기준일 | 행동 신호 기간 | 결과 확인 기간 |
|---|---|---|---|
| 학습 | 2022-08-22, 09-05, 09-19, 10-03, 10-17 | 기준일 − 60일 ~ 기준일 | 기준일 ~ 기준일+14일 |
| 검증 | 2022-11-07 | 기준일 − 60일 ~ 기준일 | **계산 금지** |
| 최종 평가 | 2022-11-23 | 기준일 − 60일 ~ 기준일 | **계산 금지** |

- 경계 조건: 행동 신호는 `[기준일 − 60일, 기준일)`, 결과는 `[기준일, 기준일 + 14일)` 반열린구간만 쓴다.
- **겹침 방지 확인:** 학습 기준일 중 마지막(10-17)의 결과 기간은 10-31에 끝나 검증 기준일(11-07) 이전이다. 검증 결과 기간(가정상 ~11-20)도 최종 평가 기준일(11-23) 이전에 끝난다. 미래 정보가 학습에 섞이지 않는다.
- **이상일 표시:** 최종 평가 결과 기간(11-23~12-06, 이번 단계에서는 계산하지 않음)에 `remove_from_cart` 이상일(2022-12-04, [`00_analysis_rules.md`](00_analysis_rules.md) 6번)이 포함된다. 추후 단계에서 결과를 계산할 때 민감도 확인 대상이다.
- **검증·최종 결과 미계산 확인:** [`10_build_snapshots.py`](../scripts/10_build_snapshots.py)는 검증·최종 기준일에 대해 `product_buy`를 조회하는 코드 자체가 없다(학습 기준일 루프에서만 결과 라벨을 계산함) — 계산했다가 버리는 것이 아니라 애초에 실행하지 않는다.

### 1-4. 행 단위와 표본

- 한 행은 (고객, 기준일)이다. 같은 고객이 여러 학습 기준일에 들어갈 수 있다(학습 스냅샷 500,000행 중 고유 고객 492,497명 — 약 1.5%는 2개 이상 기준일에 중복 등장).
- 모집단이 500~600만 명으로 전체를 쓰기엔 처리가 어려워, **기준일별로 구매 여부(0/1)로 층화한 무작위 표본(seed=42)을 기준일당 최대 100,000명**으로 뽑았다(5개 기준일 모두 모집단이 기준을 초과해 전부 표본 사용, 학습 스냅샷 전체 500,000행). 표본 크기는 처리 가능한 규모로 임의 설정한 구현상의 선택이며, 가설 판정 기준(IV 임계값 등)과는 무관하다.

## 2. 변수 정의

모든 변수는 기준일 이전 정보만 쓴다. 기간을 따로 적지 않은 변수는 60일 신호 기간(`[기준일-60, 기준일)`) 기준이다. 해당 행동이 없을 때 NULL로 두는 변수와, "횟수"로서 0이 정의상 맞아 0으로 채우는 변수를 구분해 표시했다. 동시 타임스탬프가 있을 때의 2차 정렬 기준(H2 보류상품 판정에 적용)은 timestamp 내림차순 다음 이벤트 종류 우선순위(구매>제거>담기) — 동시면 "보류 아님"으로 보수적으로 처리한다([`00_analysis_rules.md`](00_analysis_rules.md) 5번).

### H1. 최근 활동 변수

| 변수 | 구분 | 계산식 | 원천 테이블 | 기간 | 결측 처리 |
|---|---|---|---|---|---|
| `h1_days_since_last_activity` | 핵심 | 기준일 − MAX(timestamp) | 5개 이벤트 테이블 전체 | 60일 | 모집단 정의상 결측 없음 |
| `h1_days_since_last_visit` | 보조 | 기준일 − MAX(timestamp) | page_visit | 60일 | 방문 없으면 NULL |
| `h1_days_since_last_cart_add` | 보조 | 기준일 − MAX(timestamp) | add_to_cart | 60일 | 담기 없으면 NULL |
| `h1_active_days_last30` | 보조 | COUNT(DISTINCT 활동일) | 5개 이벤트 테이블 전체 | 30일 | 활동 없으면 0(모집단 정의상 발생 안 함) |
