# Phase 1 프로젝트 방향 제안

Phase 1 검증 결과를 바탕으로 가능한 프로젝트 주제 3개를 제안합니다. 여기서
어떤 주제로 확정할지는 사용자 검토 후 결정하며, Phase 1 자체는 주제를
임의로 확정하지 않습니다 (PROJECT_GUIDELINES.md 규칙).

---

## ✅ 선행조건(BLOCKER) — [해결됨, 2026-08-05] Phase 5\~6 착수 전 결정 완료

**상태: 해결됨.** 프로젝트 주제는 **A안(구매 비활성 위험 예측 + CRM 타기팅)** 으로
확정됐고, 아래 우측 검열 문제는 사용자 확인을 거쳐 처리 방침이 결정됐습니다.
결정 전문은 `docs/methodology.md`("프로젝트 주제 확정(A안) 및 우측
검열(right-censoring) 고객 처리 방침" 항목), 로그는
`docs/decisions_pending_review.md`("우측 검열 고객 처리 방침
[결정 완료]" 항목) 참고. 아래는 결정 당시의 원본 blocker 기록입니다.

> **우측 검열(right-censoring) 고객 처리 방침**
> 8.10에서 확인된 대로, 관측 종료(2022-12-08) 14일 이내에 처음 등장한 고객은
> 전체 1,822,194명(8.17%)이며, 이 중 구매 고객은 **138,041명(구매자의
> 15.18%)** 입니다. 이 고객들은 "마지막 구매 이후 14일간 재구매가 없었다"는
> 사실 자체가 관측 종료 시점과 겹쳐서, **실제로 비활성인지 아니면 단순히
> 데이터가 거기서 끊긴 것인지 구분할 수 없습니다.** 이 상태로 "14일 비활성
> = 이탈"이라는 레이블을 그대로 학습에 사용하면, 모델이 "관측 종료 시점에
> 가까운 고객"과 "진짜 비활성 고객"을 구분하지 못하고 학습하게 되어 레이블
> 노이즈가 체계적으로 발생합니다.
>
> 검토해야 할 선택지(Phase 5\~6 시작 시 사용자와 함께 결정, 지금 임의로
> 확정하지 않음):
> 1. 우측 검열 대상 고객을 학습/평가 데이터에서 아예 제외
> 2. Label window를 관측 종료보다 충분히 이전(예: 관측 종료 14일+ 이전)의
>    snapshot_date만 사용하도록 Phase 5 스냅샷 설계 자체에서 원천 차단
> 3. 검열을 명시적으로 다루는 생존분석(survival analysis) 계열 접근
>
> 근거: `reports/phase1_observation_period.md`, `docs/limitations.md` (1, 2번 항목)

이 문서의 나머지 제안들은 모두 위 blocker가 해결됐다는 전제 위에서만
Phase 5로 넘어갈 수 있습니다.

## 주제 A. 구매 비활성 위험 예측 + CRM 타기팅 시뮬레이션 (권장, PROJECT_GUIDELINES.md 원 목표와 가장 부합)

**해결하려는 문제**: 제한된 CRM 접촉 자원 안에서, 구매 비활성 위험이 높은
고객과 향후 구매 가능성이 높은 고객을 단순 규칙(최근성 등)보다 효율적으로
선별할 수 있는가.

**필요한 데이터**: product_buy, add_to_cart, page_visit, search_query 전체 +
product_properties (카테고리). 이미 확보·검증 완료.

**가능한 KPI**: Precision@5/10/20%, Recall@5/10/20%, Lift@5/10/20%, 단순
규칙(최근성) 대비 개선율, 동일 포착률에 필요한 접촉 인원 감소율.

**가능한 모델**: 로지스틱 회귀 → 트리 기반(LightGBM 등) 순서로 단순→복잡
비교. 반드시 최근성 규칙과 무작위 기준선을 함께 비교(PROJECT_GUIDELINES.md 20번).

**대시보드 구성**: PROJECT_GUIDELINES.md Phase 7의 7개 페이지 구성(Overview, Funnel,
Cohort&Retention, Lifecycle, Segment Explorer, Targeting Simulator, AI CRM
Report)을 그대로 사용 가능.

**LLM 활용 방식**: SQL 집계·모델 예측 결과를 Pydantic으로 구조화해 LLM에
전달, Data Facts/Model Predictions/Recommended Actions/Testable Hypotheses
4영역으로 구분된 리포트 생성 (PROJECT_GUIDELINES.md 27\~28번).

**장점**
- PROJECT_GUIDELINES.md가 이미 상세히 설계해둔 Phase 2\~9와 1:1로 대응해 재작업이 적음
- "구매 비활성"과 "구매성향" 두 모델을 함께 다뤄 CRM 실무(재활성화 vs 구매유도)
  구분이 명확함
- Phase 1에서 이미 장바구니↔구매 시간 연결, 구매 전 탐색량 차이 등 예측
  feature 후보가 될 만한 신호를 다수 확인함(8.7\~8.9)

**한계**
- 위 blocker(우측 검열) 해결 전에는 레이블 품질을 신뢰할 수 없음
- 6개월 스냅샷이라 장기(90일+) 이탈은 애초에 관측 불가 → 14일/28일 단기
  비활성 정의만 현실적
- 데이터가 2022년 하반기라 "현재 고객 행동"이라 주장 불가(`docs/methodology.md`)

**예상 면접 질문**
- "왜 2023년 이후 데이터가 아니라 2022년 데이터를 썼나요?" → 정책 결정 근거(`docs/methodology.md`) 제시
- "이탈률을 실제로 개선했다고 할 수 있나요?" → 아니요, 과거 데이터 기반 대상 선정 효율만 검증(PROJECT_GUIDELINES.md 5번)
- "우측 검열 문제를 어떻게 처리했나요?" → 위 blocker 절 참고, 처리 방침을 명시적으로 설명해야 함

## 주제 B. 장바구니 이탈(Cart Abandonment) 특화 CRM

**해결하려는 문제**: 장바구니에 상품을 담았지만 구매하지 않은 고객을 어떻게
우선순위화해 재유입시킬 것인가에 집중하는 좁은 스코프 버전.

**필요한 데이터**: add_to_cart, remove_from_cart, product_buy, product_properties.

**가능한 KPI**: 장바구니→구매 전환율(8.8에서 이미 20.27% 확인), 미전환 고객의
재접촉 후 가상 전환 가능성(모델 기반 우선순위).

**가능한 모델**: 이진 분류(장바구니 추가 후 N일 내 구매 여부) — 데이터가 이미
add→buy 시간 간격(median 0.12h)을 보여줘 feature 설계가 상대적으로 쉬움.

**대시보드 구성**: 전체 7페이지 중 Funnel, Segment Explorer, Targeting
Simulator를 장바구니 중심으로 축소 구성.

**LLM 활용 방식**: 주제 A와 동일한 파이프라인이나 리포트 스코프를 장바구니
이탈로 한정.

**장점**: 스코프가 좁아 구현 속도가 빠르고, 8.8에서 이미 핵심 신호(전환율,
소요시간)를 확인해 feasibility가 가장 높음. 세션 ID 없이도 (client_id, sku)
쌍 단위로 명확하게 분석 가능함을 이미 검증(8.8).

**한계**: PROJECT_GUIDELINES.md가 요구하는 "고객 라이프사이클 전반"을 다루지 못해 프로젝트
스코프가 PROJECT_GUIDELINES.md 원 설계보다 좁아짐. 재활성화(비활성 위험) 같은 다른 CRM
목적은 별도로 다루지 않으면 누락됨.

**예상 면접 질문**
- "왜 전체 라이프사이클이 아니라 장바구니만 봤나요?" → 스코프를 좁혀 깊이 있게
  다룬 트레이드오프 설명 필요
- "버스트 이벤트(5초 이내 반복) 처리는 어떻게 했나요?" → `docs/decisions_pending_review.md` 참고, 특히 이 주제에서는 add_to_cart 버스트(4.72%)가 직접 영향

## 주제 C. 고객 라이프사이클 세그먼트 기반 우선순위 시스템 (예측모델보다 해석 가능성 강조)

**해결하려는 문제**: 복잡한 예측 모델 대신, 관찰 가능한 행동 규칙(구매 간격,
활동일 수, 이벤트 조합 등)으로 고객을 세그먼트화해 CRM 목적별로 우선순위를
정하는 데 집중.

**필요한 데이터**: 전체 이벤트 테이블 (모델링용 feature 엔지니어링 없이 집계
지표 위주로 사용).

**가능한 KPI**: 세그먼트별 구매율·구매주기·재접촉 필요도, 세그먼트 규칙 대비
모델 기반 타기팅의 개선폭(비교 대상으로만 가벼운 모델 사용).

**가능한 모델**: 규칙 기반 세그먼트가 주력, 군집분석(K-means 등)은 보완적
탐색 용도로만 사용(PROJECT_GUIDELINES.md 17번 원칙과 일치).

**대시보드 구성**: Segment Explorer 페이지를 중심으로 확장, Targeting
Simulator는 세그먼트 단위 필터로 단순화.

**LLM 활용 방식**: 세그먼트별 특성 요약과 추천 액션 생성에 특화 — 예측 확률보다
"이 세그먼트는 이런 행동 패턴을 보인다"는 서술적 리포트에 집중.

**장점**: 모델 성능(AUC 등)에 대한 설명 부담이 적고, 비개발자 이해관계자(CRM
담당자)에게 설명하기 쉬움. 8.6\~8.10에서 발견한 구조적 특징(대다수 단발성
방문, long-tail 이상치 등)을 세그먼트 정의에 바로 활용 가능.

**한계**: "모델 기반 타기팅이 단순 규칙보다 효율적인가"라는 PROJECT_GUIDELINES.md 핵심
질문(4번 섹션)에 대한 답을 주제 A만큼 강하게 제시하지 못함 — 비교 대상이
약해짐.

**예상 면접 질문**
- "왜 모델을 메인으로 쓰지 않았나요?" → 해석 가능성과 실무 적용성을 우선한
  선택이었음을 설명, 다만 비교용 모델은 포함했음을 강조
- "세그먼트 기준을 어떻게 정했나요?" → 임의로 정하지 않고 실제 분포(8.6\~8.10)를
  근거로 정했음을 PROJECT_GUIDELINES.md 17번 원칙과 함께 설명

## 제 의견 (참고용, 결정 아님)

주제 A가 PROJECT_GUIDELINES.md 전체 설계(Phase 2\~10)와 가장 정합적이고, Phase 1에서 확보한
증거(feasibility report)도 A를 가장 폭넓게 뒷받침합니다. 다만 위 **blocker(우측
검열 처리 방침)** 를 먼저 결정하지 않으면 어떤 주제를 선택하든 Phase 5로
진행할 수 없습니다.
