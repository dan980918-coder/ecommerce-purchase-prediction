# PROJECT_GUIDELINES.md

## 1. 프로젝트 개요

### 프로젝트명

**이커머스 고객 행동 퍼널 분석 및 CRM 타기팅 전략 설계** (Predicting Churn & Purchase Intent for CRM Targeting)

### 프로젝트 목적

실제 이커머스 고객의 검색, 방문, 장바구니, 구매 행동을 통합하여 고객 라이프사이클을 분석하고, 구매 비활성 위험 고객과 향후 구매 가능성이 높은 고객을 식별한다.

최종적으로 제한된 CRM 접촉 자원 안에서 다음 고객을 우선 선정할 수 있는 분석 시스템을 구축한다.

* 재활성화가 필요한 고객
* 구매 유도가 필요한 고객
* 장바구니 이탈 고객
* 반복구매 가능성이 높은 고객
* 접촉 우선순위가 낮은 고객

이 프로젝트는 실제 CRM 캠페인을 집행해 이탈률이나 매출을 직접 개선한 프로젝트가 아니다.

프로젝트에서 검증할 수 있는 핵심 성과는 다음과 같다.

> 단순 규칙이나 무작위 타기팅보다 구매 비활성 위험 고객과 향후 구매 고객을 더 효율적으로 선별할 수 있는가?

## 2. 사용 데이터

### 데이터셋

**Synerise RecSys Challenge 2025 원본 데이터**

실제 온라인 리테일 서비스에서 발생한 익명화 고객 행동 로그를 사용한다.

주요 데이터 테이블은 다음과 같다.

* `page_visit`
* `search_query`
* `add_to_cart`
* `remove_from_cart`
* `product_buy`
* `product_properties`

### 데이터 사용 원칙

* 공식 Synerise 배포본만 사용한다.
* Kaggle이나 비공식 복제본을 우선 사용하지 않는다.
* 원본 데이터는 GitHub에 업로드하지 않는다.
* 데이터 출처와 라이선스를 README에 표시한다.
* 공개 대시보드에는 원본 고객별 행동 로그를 포함하지 않는다.
* 공개 결과물에는 집계 데이터, 모델 평가 결과, 합성 샘플만 포함한다.
* 고객 ID는 외부에 그대로 노출하지 않는다.
* 원본 데이터를 복원할 수 있는 세부 테이블을 공개하지 않는다.

## 4. 프로젝트의 핵심 질문

프로젝트는 다음 질문을 중심으로 구성한다.

### 고객 이해

1. 고객은 탐색에서 구매까지 어떤 행동 경로를 보이는가?
2. 어떤 고객이 반복구매자로 이어지는가?
3. 첫 관측 구매 이후 재구매율은 어떻게 변하는가?
4. 구매가 감소하기 전에 어떤 행동 변화가 나타나는가?
5. 장바구니 추가와 제거 행동은 이후 구매와 어떤 관계가 있는가?
6. 고객은 어떤 라이프사이클 상태로 구분할 수 있는가?

### CRM 타기팅

1. 향후 일정 기간 구매하지 않을 가능성이 높은 고객은 누구인가?
2. 향후 일정 기간 구매할 가능성이 높은 고객은 누구인가?
3. 장바구니 행동은 있지만 구매하지 않을 고객은 누구인가?
4. 전체 고객 중 일부만 접촉할 때 누구를 선택해야 하는가?
5. 모델 기반 타기팅은 단순 최근성 규칙보다 효율적인가?

### 실무 활용

1. CRM 담당자가 대시보드에서 접촉 비율을 선택할 수 있는가?
2. 고객 세그먼트별로 다른 CRM 목적을 제안할 수 있는가?
3. SQL로 계산한 결과를 LLM이 정확하게 설명할 수 있는가?
4. 사실, 모델 예측, LLM 제안을 명확하게 구분할 수 있는가?

## 5. 프로젝트에서 주장할 수 있는 것과 없는 것

### 주장할 수 있는 것

* 고객행동 기반 CRM 데이터마트를 구축했다.
* 고객 퍼널, 코호트, 리텐션, 구매주기를 분석했다.
* 고객 라이프사이클과 행동 세그먼트를 설계했다.
* 구매 비활성 위험과 향후 구매 가능성을 예측했다.
* 단순 규칙 대비 고객 선정 효율을 비교했다.
* 동일한 접촉 인원에서 위험 고객 포착률을 높였다.
* 동일한 포착률을 달성하는 데 필요한 접촉 인원을 줄였다.
* 분석 결과를 대시보드와 LLM 리포트로 연결했다.

### 주장하면 안 되는 것

* 실제 이탈률을 개선했다.
* 실제 매출을 증가시켰다.
* CRM 캠페인 전환율을 향상했다.
* 쿠폰 효과를 검증했다.
* 실제 고객생애가치를 계산했다.
* 실제 캠페인 ROI를 개선했다.
* 기업이 모델을 운영에 적용했다.
* 모델이 원인적으로 고객 행동을 변화시켰다.

성과 표현은 반드시 다음 형태를 따른다.

```text
실제 비즈니스 KPI 개선
X

과거 행동 데이터를 이용한 대상 선정 효율 개선
O
```

## 8. Phase 1에서 수행할 작업

### 8.1 데이터 다운로드

공식 Synerise 데이터 페이지에서 원본 데이터를 다운로드한다.

원본 데이터와 전처리된 대회용 데이터가 모두 있을 경우 원본 데이터의 구조를 우선 확인한다.

다운로드 후 다음을 기록한다.

* 파일명
* 파일 크기
* 압축 파일 크기
* 압축 해제 후 크기
* 파일별 형식
* 체크섬
* 다운로드 날짜
* 데이터 라이선스
* 공식 출처

### 8.2 파일 구조 검사

모든 파일에 대해 다음을 출력한다.

* 파일명
* 행 수
* 열 수
* 컬럼명
* 데이터 타입
* 파일 크기
* 첫 5행
* 마지막 5행
* 결측값 수
* 고유값 수
* 예상 PK 후보
* 중복 행 수

Parquet 파일은 전체를 Pandas로 메모리에 올리지 않는다.

DuckDB 또는 Polars의 lazy scan을 우선 사용한다.

### 8.3 타임스탬프 검증

모든 이벤트 테이블에 대해 다음을 계산한다.

```sql
SELECT
    MIN(timestamp) AS min_timestamp,
    MAX(timestamp) AS max_timestamp,
    COUNT(*) AS row_count,
    COUNT(DISTINCT client_id) AS unique_clients
FROM event_table;
```

모든 결과를 하나의 표로 저장한다.

예시:

| event_type       | min_timestamp | max_timestamp | rows | clients |
| ---------------- | ------------- | ------------- | ---: | ------: |
| product_buy      |               |               |      |         |
| add_to_cart      |               |               |      |         |
| remove_from_cart |               |               |      |         |
| page_visit       |               |               |      |         |
| search_query     |               |               |      |         |

검증 결과 데이터가 "최근 3년" 기준을 충족하지 못하더라도 그 사실만으로는
Phase 1을 중단하지 않는다. 대신 관측 기간을 투명하게 명시하고, 데이터
최신성 관련 한계는 `docs/limitations.md`에 기록한 채로 Phase 1을 계속
진행한다.

### 8.4 고객 ID 연결성 검사

다음 고객 수를 계산한다.

* 전체 고유 고객
* 구매 고객
* 장바구니 고객
* 검색 고객
* 페이지 방문 고객
* 구매와 장바구니가 모두 있는 고객
* 구매와 검색이 모두 있는 고객
* 다섯 이벤트가 모두 있는 고객
* 하나의 이벤트만 가진 고객

이벤트 간 고객 ID 교집합과 합집합을 확인한다.

고객별 이벤트 타입 수 분포도 계산한다.

### 8.5 상품 ID 연결성 검사

다음을 확인한다.

* 구매 상품 수
* 장바구니 상품 수
* 상품 속성 테이블 상품 수
* 구매 상품과 상품 속성 테이블 매칭률
* 장바구니 상품과 상품 속성 테이블 매칭률
* 카테고리 결측률
* 가격구간 결측률
* 중복 상품 속성
* 한 상품에 여러 속성값이 존재하는지

가격은 실제 금액이 아니라 구간 또는 순위형 값일 수 있으므로 실제 매출로 해석하지 않는다.

### 8.6 이벤트 품질 검사

다음을 확인한다.

* 완전 중복 행
* 동일 고객·동일 시각·동일 상품·동일 이벤트 중복
* 타임스탬프 파싱 오류
* 고객 ID 결측
* 상품 ID 결측
* 비정상적으로 많은 이벤트를 가진 고객
* 비정상적으로 짧은 시간에 반복된 이벤트
* 고객별 첫 행동과 마지막 행동
* 고객별 관찰일 수
* 이벤트가 집중된 특정 날짜
* 로그 수집 중단 또는 급증 구간

### 8.7 구매행동 검사

다음을 계산한다.

* 구매 고객 수
* 고객당 구매 이벤트 수
* 고객당 고유 구매일 수
* 고객당 고유 구매 상품 수
* 고객당 구매 카테고리 수
* 고객별 첫 관측 구매일
* 고객별 마지막 관측 구매일
* 고객별 구매 간격
* 구매 1회 고객 비율
* 구매 2회 이상 고객 비율
* 구매 3회 이상 고객 비율
* 반복구매가 가능한 고객 수
* 관찰 종료 직전 구매 고객 비율

구매 간격은 다음을 확인한다.

* 평균
* 중앙값
* 25·75 분위수
* 90·95 분위수
* 고객별 평균 구매간격
* 고객별 구매간격 변동성

### 8.8 장바구니 행동 검사

다음을 계산한다.

* 장바구니 추가 고객 수
* 장바구니 제거 고객 수
* 추가와 제거를 모두 한 고객 수
* 고객별 추가 횟수
* 고객별 제거 횟수
* 상품별 추가 횟수
* 상품별 제거 횟수
* 추가 후 동일 상품 구매 가능성
* 추가 후 구매까지 걸린 시간
* 제거 후 구매한 사례
* 장바구니 이벤트와 구매 이벤트의 시간 연결 가능성

세션 ID가 없다면 임의로 세션을 확정하지 않는다.

세션화가 필요할 경우 다음 후보만 검토한다.

* 30분 비활동 기준
* 60분 비활동 기준
* 일 단위 고객 행동

실제 분포를 확인한 뒤 결정한다.

### 8.9 페이지 방문과 검색 검사

다음을 확인한다.

* 고객별 페이지 방문 횟수
* 고객별 검색 횟수
* 활동일 수
* 구매 전 방문·검색량
* 비구매 고객의 방문·검색량
* 방문 URL과 상품 ID의 연결 가능성
* 검색어 원문의 존재 여부
* 검색어가 임베딩 또는 양자화 값인지
* 해석 가능한 텍스트 필드 존재 여부

상품 페이지와 특정 상품 구매가 직접 연결되지 않으면 상품 단위 퍼널을 만들지 않는다.

고객 단위 탐색 퍼널만 검토한다.

### 8.10 관찰기간과 검열 문제

다음을 확인한다.

* 고객별 첫 관측일
* 고객별 마지막 관측일
* 고객별 관찰기간
* 데이터 시작 시점에 이미 활동 중인 고객
* 데이터 종료 시점 직전 처음 등장한 고객
* 첫 관측 구매를 실제 첫 구매로 볼 수 없는 문제
* 마지막 관측 이후 행동을 알 수 없는 문제

다음 표현을 사용한다.

```text
신규 고객
X

첫 관측 고객
O
```

```text
첫 구매
X

첫 관측 구매
O
```

```text
진정한 고객생애가치
X

6개월 관찰가치 또는 행동가치
O
```

## 10. Phase 1 중단 조건

다음 중 하나라도 발생하면 분석을 계속하지 않고 보고한다.

* 데이터가 공식 배포본인지 확인할 수 없음
* 이용 조건을 확인할 수 없음
* 타임스탬프가 최근성 기준을 벗어나는 것만으로는 중단하지 않는다. 대신 관측 기간을 투명하게 명시하고 진행한다.
* 고객 ID가 이벤트 간 연결되지 않음
* 구매 반복 고객이 너무 적음
* 상품 테이블 매칭률이 지나치게 낮음
* 주요 컬럼 설명이 공식 문서와 다름
* 파일이 손상됐거나 일부 누락됨
* 코호트·리텐션·타기팅 분석이 구조적으로 불가능함

Phase 1 완료 후 검토 없이 Phase 2로 넘어가지 않는다.

SQL에서 확인된 사실

모델의 예측 결과

### Recommended Actions

LLM이 제안한 CRM 액션

### Testable Hypotheses

실제 캠페인 실험으로 검증해야 하는 가설

* 코호트 리텐션 값이 0~1 범위를 벗어나지 않음
* 고객별 첫 관측 구매일이 최소 구매일과 일치
* 구매간격이 음수가 아님
* 타기팅 비율과 선정 고객 수가 일치

## LLM 테스트

* 숫자 환각 금지
* 사실·예측·제안 구분
* 입력에 없는 KPI 생성 금지
* 성과 과장 표현 금지
